# 审批发起路径与线性流程设计

## 目标

- 修复审批详情成功加载后仍提示“申请加载失败”的误报。
- 在发起申请时明确展示审批节点、审批方式和审批人。
- 新建流程暂时只支持单人审批和会签，不再提供新增条件分支入口。
- 保持历史条件流程可读取、可运行，不改动已发布流程快照。
- 本期不实现流程应用删除。

## 交互设计

### 审批详情

详情请求成功时先复制普通响应数据，再写入 Vue 响应式状态。真实加载失败时显示错误结果页和重试按钮，不展示半成品详情。

### 发起申请

选择流程应用后，在申请表单前展示“审批路径”表格：

- 顺序
- 审批节点
- 审批方式（单人审批或会签）
- 审批人

审批人名称来自启用员工数据。历史流程包含条件节点时，列出所有可能审批节点，并提示实际路径由表单内容决定。

### 流程设计器

所有新增节点菜单仅保留“单人审批”和“会签”。已有条件节点继续按原结构展示和运行，避免破坏历史数据。

## 验收

- 打开已有申请详情不再出现错误提示。
- 真实详情接口失败时显示错误页，可重新加载。
- 选择流程应用后可看见节点及审批人。
- 新流程设计器没有“条件分支”新增入口。
- 历史条件流程相关后端测试保持通过。
- 前端类型检查、构建及审批 E2E 通过。
