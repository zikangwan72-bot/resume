# 易读型所见即所得流程编辑器设计规格

> 日期：2026-07-30  
> 状态：用户已确认交互设计，待书面规格审核

## 1. 目标

在现有统一流程应用基础上，降低创建、阅读和操作成本。流程管理员无需理解节点 ID、连线或图结构术语，也能完成表单和审批流程配置。

本次改造包含：

- 流程分类创建与分组展示。
- 自动生成唯一流程编码。
- 表单设计、预览和运行页面共用真实渲染组件。
- 将流程设计收敛为单人审批、会签、条件分支三种规则。
- 增加退回上一步、重新提交、驳回发起人、转审和同意提交动作。
- 检查并修复全部表单组件的编辑、预览、校验和提交行为。

不引入 BPMN、自由连线、循环、复杂并行网关或脚本条件。

## 2. 设计原则

1. 业务语言优先：界面不展示节点 ID、边、默认路径等技术概念。
2. 从上到下阅读：流程顺序与实际执行顺序一致。
3. 所见即所得：设计、预览、发起和审批使用同一套表单渲染组件。
4. 系统维护结构：开始、结束、路径汇合和连线由系统自动处理。
5. 操作最少：常用动作直接呈现，高级设置进入右侧属性面板。
6. 旧数据兼容：保留现有流程版本、历史实例和已保存定义。

## 3. 基本信息与分类

### 3.1 创建字段

创建流程时填写：

- 流程名称
- 流程分类
- 流程说明

流程编号不允许手工输入。

### 3.2 自动流程编码

编码格式：

```text
分类英文缩写-创建日期-4位随机大写字母或数字
```

示例：

```text
HR-20260730-A7K3
FIN-20260730-M8Q2
```

预设分类使用固定英文缩写；自定义分类使用规范化英文首字母或通用前缀 `CUS`。编码由后端生成并通过数据库唯一约束保证不重复。创建完成后只读显示，后续版本沿用同一编码。

### 3.3 分类规则

内置分类：

- 人事
- 财务
- 采购
- 行政
- 通用

管理员可以输入并保存自定义分类。发起申请页按照分类分组展示；分类内流程按名称排列。空分类不显示。

## 4. 所见即所得表单编辑器

### 4.1 三栏结构

- 左侧：字段组件库。
- 中间：真实运行表单，可选择和排序字段。
- 右侧：当前字段属性。

点击左侧组件后，中间立即生成对应的真实表单控件。点击中间字段后，右侧显示属性设置。字段支持拖动排序，也保留上移和下移按钮。

### 4.2 共用渲染组件

抽取单一表单渲染层，供以下场景共用：

- 管理员表单设计
- 管理员预览
- 员工发起申请
- 审批详情

设计态只增加选中框、排序和删除控件，不另写一套字段卡片。修改标题、说明、提示、必填或选项后，中间区域立即更新。

### 4.3 字段组件

必须逐项验证：

- 单行文本、多行文本
- 数字、金额
- 日期、日期范围
- 单选、多选、下拉选择
- 人员、部门
- 附件上传
- 分组标题
- 明细表格

附件在设计和预览中显示真实上传区域；预览不永久保存文件。明细表格显示真实列标题、输入控件、添加行和删除行操作。设计态可以配置列名称、稳定字段键、类型和必填规则，不允许嵌套明细表格。

## 5. 易读型流程设计器

### 5.1 节点类型

只提供：

- 单人审批
- 会签
- 条件分支

开始和结束节点由系统生成，不作为可添加组件。

### 5.2 添加与阅读方式

流程固定从上到下展示。每个节点下方提供加号按钮，点击后直接选择下一节点类型。用户不需要先选择节点，再到顶部工具栏寻找添加按钮。

单人审批节点直接显示审批人。会签节点显示全部审批人和“全部同意后继续”。节点属性面板只保留：

- 节点名称
- 审批人
- 是否允许转审
- 超时时间

### 5.3 条件分支

条件使用结构化自然语言：

```text
字段 + 判断方式 + 比较值
```

示例：

```text
采购金额判断
├─ 金额大于等于 5,000 元：财务会签
└─ 其他情况：部门经理审批
```

每条分支使用独立区域，直接显示条件、审批方式和审批人。“其他情况”始终存在，不能删除。分支完成后由系统自动汇合，不要求管理员配置汇合节点。

条件按界面顺序匹配，第一条命中分支生效；未命中时进入“其他情况”。条件只能引用可比较的表单字段。

## 6. 双视角预览

预览页提供：

### 6.1 发起人视角

显示真实表单、附件、明细表格、保存草稿和提交申请按钮。

### 6.2 审批人视角

显示申请内容、审批意见和审批操作栏。按钮与运行页面保持相同样式和位置，但预览状态不调用审批接口。

## 7. 审批动作与状态流转

### 7.1 审批人操作

- 退回上一步
- 驳回发起人
- 转审
- 同意并提交

转审仅在节点启用“允许转审”时显示。退回和驳回必须填写原因。

### 7.2 退回上一步

“退回”表示局部返工，不结束流程。

1. 当前审批节点选择退回上一步。
2. 系统记录退回来源节点、目标节点、处理人、时间和原因。
3. 上一处理节点重新进入待处理状态。
4. 上一处理人修改或补充内容后点击“修改后重新提交”。
5. 流程回到原退回来源节点，由该节点继续审批。

如果当前节点是第一个审批节点，则“退回上一步”退回发起人修改；发起人重新提交后回到该第一个审批节点。

### 7.3 驳回发起人

“驳回”立即结束当前流程实例，状态变为已驳回。发起人只能查看历史记录；如需继续，重新发起新申请。

### 7.4 转审

转审将当前待办转给另一名启用用户，不改变流程节点位置。系统记录原审批人、目标审批人、时间和原因。

### 7.5 同意并提交

单人审批同意后进入下一节点。会签需要全部审批人同意；任一审批人驳回则流程结束。

## 8. 数据与接口调整

- 流程创建接口不再要求前端提交 `code`，由后端生成。
- `process_apps.code` 继续保持唯一且不可变。
- 分类字段继续兼容已有字符串值。
- 审批节点和操作日志增加退回、重新提交所需状态与动作类型。
- 运行实例保存退回来源节点和返工目标，保证重新提交回到正确位置。
- 已发布版本和运行实例继续使用快照，历史流程不被新版编辑器覆盖。
- 旧流程定义在读取时转换为新编辑器视图，保存草稿时再使用现有稳定字段 ID 和节点 ID 格式落库。

## 9. 校验与错误处理

发布前校验：

- 至少有一个业务字段。
- 至少有一个审批节点。
- 审批人有效且启用。
- 会签至少有两名不同审批人。
- 条件字段、判断方式和值有效。
- 每个条件分支存在“其他情况”。
- 每条路径最终能够结束。

错误显示在对应字段或节点附近；顶部只显示错误数量摘要。点击错误后自动切换到对应步骤并定位目标。保存失败时保留本地编辑内容。

审批动作使用事务处理。节点状态、实例状态和操作日志必须同时成功或同时回滚。重复操作返回明确中文提示，不重复写日志。

## 10. 测试与验收

### 10.1 后端

- 自动编码格式和唯一性。
- 预设分类与自定义分类兼容。
- 单人审批、会签和条件分支推进。
- 第一个节点退回发起人。
- 中间节点退回上一处理人并重新提交。
- 重新提交回到原退回来源节点。
- 驳回结束流程。
- 转审权限和审计记录。
- 旧版本与历史实例兼容。

### 10.2 前端

- 发起页按分类分组。
- 创建页流程编码只读且自动展示。
- 所有字段组件的添加、编辑、复制、排序、删除、预览、校验和提交。
- 附件与明细表格在设计、预览和运行页面表现一致。
- 单人审批、会签和条件分支易读展示。
- 双视角预览不产生真实提交。
- 退回、驳回、转审和同意提交按钮按权限正确显示。
- 发布错误可以定位到字段或节点。
- 桌面、平板和手机宽度无重叠、遮挡或文本溢出。

### 10.3 核心验收场景

1. 创建人事流程，仅填写名称、分类和说明，系统自动生成编码。
2. 添加文本、附件和明细表格，在中间直接看到真实表单。
3. 配置“金额大于等于 5,000 元”与“其他情况”两条分支。
4. 预览发起人和审批人视角，确认与运行页面一致。
5. 发布后从按分类分组的发起页提交申请。
6. 审批人退回上一步，上一处理人修改后重新提交，流程回到原审批节点。
7. 验证驳回结束流程、转审更换审批人、会签全部同意后继续。
8. 打开旧流程与历史实例，确认数据和展示正常。
